# 小红书短文案 · 文风自查清单

> **用途：** 笔记定稿前，去掉 AI 腔、翻译腔与空泛评价，保持口语可信。  
> **来源：** 从 [grapeot/writing-skill](https://github.com/grapeot/writing-skill) 的 `external_prose_lint` / `rules.py` **抽取并改写**，仅保留适合**短文案**的条目。  
> **不是：** 对外长文 lint、不是 `external-prose-lint` CLI、不跑 Python 也能用（Agent/人逐条对照即可）。

---

## 自动化

Owner **不用**说「按 xhs-copy-self-check 自查」。只要 Agent **写入或改** `content/xiaohongshu/` 下 Markdown，项目规则 **`.cursor/rules/xhs-copy-quality.mdc`** 会要求定稿前自动跑禁词脚本并对照本清单。

## Agent 边界（必读，防混淆）

| 场景 | 用本清单 | 不要用 |
|------|----------|--------|
| 小红书标题 / 钩子 / 正文 / CTA / 标签 | ✅ 本文件 | ❌ writing-skill 全文 / external-prose-lint |
| 选题是否对齐 IP、涨粉、强链接 | ❌ 本文件 | ✅ `kernels/xiaohongshu/` · `verify-xhs-topic.sh` |
| 商业长文、专栏、2000 字+ 分析稿 | ❌ 本文件 | ✅ 若将来接入 writing-skill，走**长文**流程 |
| 听见 Daily 栏目 | ❌ 本文件 | ✅ `danying-tingjian-daily` skill |

**顺序建议：** Brief / 成稿 →（可选）Topic Manager `evaluate` → **本清单文风自查** → `content/xiaohongshu/` commit。

**小红书特例（以下在长文 lint 里算问题，在这里不算）：**

- 故意 **短句、一行一段** 做节奏 → 允许，不必合并成长段落。
- **总字数远小于 2000 字** → 正常。
- **不用 H2 章节、不要求 3 个行内外链** → 笔记体裁不同；若放链接，优先一句带说明，避免裸 URL 堆砌。

## 自查怎么用

1. 对着 `content/xiaohongshu/` 里**待发布稿**全文扫一遍（含标题）。  
2. **禁词机械扫描（§11）：** 在仓库根目录执行  
   `bash scripts/xhs-copy-grep-banned.sh content/xiaohongshu/你的稿件.md`  
   - `PASS` = 禁词表零命中（仍要人工看破折号、不是而是等 §1–§10）。  
   - `FAIL` = 打印行号与命中词，改稿后重跑。  
3. 下面每节：**命中则改**；不确定的在稿末加一行 `<!-- 自查保留：…理由 -->` 或交给 Owner 定。  
4. 全部 **硬项** 处理完再称「定稿」。

## 硬项 · 出现即改（除非注明例外）

### 1. 破折号情绪停顿

- **避免：** `——` / `—` 当口语停顿或补成分隔。  
- **改法：** 逗号、冒号、拆句，或直接换行（小红书常用换行）。

### 2. 括号「词典式」中英对照

- **避免：** `中文（English）`、`English（中文释义）` 当术语表。  
- **改法：** 正文只保留一种称呼；必要时首次用口语解释，不用括号词条。

### 3. 「很 X：」评价标签

- **避免：** `很直接：`、`很清晰：` 当段首引导。  
- **改法：** 删掉标签，直接写事实或场景。

### 4. 极化 / 戏剧化

- **避免：** `这根本不是`、`根本无法`、`绝不是`、`极其`、`残酷现实`、`死死锁在` 等。  
- **改法：** 中性、具体：谁、做了什么、结果如何。

### 5. 元评论开头（零内容铺垫）

- **避免：** `具体来说`、`接下来我们看`、`需要重点说明的是`、`综上所述`、`首先需要明确`。  
- **改法：** 第一句就是钩子或信息点（符合小红书前 2 行）。

### 6. 模板句「不是 A，而是 B」

- **避免：** 连续、堆砌的 `不是…，而是…`（翻译腔、假对立）。  
- **改法：** 直接写取舍或事实。

### 7. 「当……时 / 在……的时候」

- **避免：** 英文从句直译感。  
- **改法：** 主动句、顺叙（例：`练琴前先做呼吸` 而非 `当你在练琴的时候`）。

### 8. 标题书名号

- **避免：** 笔记标题用 `《…》` 包整句（除非真是书名且必要）。  
- **改法：** plain 标题，符合平台习惯。

### 9. 裸 URL

- **避免：** 正文直接贴 `https://…`。  
- **改法：** 口语指代 + 放主页/评论区说明，或 `[短标签](url)`（笔记里链接宜少）。

### 10. 连续「被」字排比

- **避免：** `被…、被…、被…` 或一句里 ≥3 个「被」。  
- **改法：** 主语回到句首（单个「被」若去掉不通顺可保留）。

### 11. 禁词表（AI 腔 / 空修辞）

命中则改成**具体动作、数字、场景或删掉**：

| 类别 | 词/短语 |
|------|---------|
| 空评价 | 值得关注、值得一提、值得注意、值得一读、意义重大、深入探讨、毫无疑问、不言而喻、至关重要、**值得**（单独作空评价时） |
| 隐喻 / 口号 | 长出来、叙事弧线、叙事弧、奠定基础、为后续奠定、疯狂发版、一地鸡毛、竞赛才刚刚开始、范式转移、闭眼编、击穿、打穿、拆解、收口、生长、赋能、颠覆性、颠覆、结构性、很稳、更稳、卡点 |
| 套路比喻 | 尺子、撑破、撑不住、算账 |
| 归属 hedging | 按我们的理解、在我们的理解、我们的理解是、按我们的推断、在我们看来、我们认为、我们觉得 |
| 脚手架 | 这意味着、从这个角度看、需要注意的是、核心要素、核心约束 |

**例外：** 技术本义（如「硬件」「硬盘」「硬编码」）、生物学「生长」、品牌专名 — 保留并在自查里一句说明。

## 软项 · 有则优化（不阻塞短笔记）

### 引号

- 概念词伪强调、拿腔拿调 → 去引号。  
- **保留：** 直接引用他人原话。

### 单个「被」字句

- 能改主动且更顺 → 改；改完拗口可保留。

### 数字密度

- 短笔记里 **一串数字罗列**（像说明书）→ 只留 1～2 个支撑判断的数字，其余删或说「约/几块/几次」。  
- 清单体笔记（如步骤 1/2/3）可保留，但避免无因果的数字墙。

### 英文词

- **保留：** 品牌名、Danying HEAR Daily、法派专有外来词、必要术语（如 AI、IP 若已口语化）。  
- **压缩：** 整段英文墙 → 中文转述 + 必要时括号缩写一次。

### 同一链接重复

- 同一 URL 反复出现 → 首次说明即可，后文用「见上文链接/主页」。
